# UX reasoning and task structure

All rows inherit RULE-BASE from [governance](../governance.md). These are design lenses, not universal numerical laws. Source identifiers resolve in [sources](../sources.md). For each applicable lens record the actual decision and test; do not merely name the law.

| ID | Applicability / strength | Authority/status; rationale | Expected behaviour | Exceptions / dependencies | Observable acceptance |
|---|---|---|---|---|---|
| UX-01 | Task/flow design; MUST | U4A; USER REQUIREMENT; task before layout | Name user goal, starting knowledge, success condition, primary/secondary actions, entity scope and exits. Order information by what enables the task; disclose secondary detail without hiding requirements or errors | D01/D02; existing task can be inherited by name | A representative user can locate the next action and explain which records it affects; error recovery returns to the task |
| UX-02 | Familiar navigation/control; DEFAULT WITH OVERRIDE | PROPOSED informed by N1; Jakob/familiarity lens | Prefer recognisable platform and product conventions. Document unfamiliar interaction's task advantage before introducing it | Counterexample: desktop hover navigation copied to touch. Familiarity cannot justify inaccessible precedent | Compare task discovery and misactivation with existing convention, using target users/input; no arbitrary layout copying |
| UX-03 | Competing choices; DEFAULT WITH OVERRIDE | PROPOSED; H1 scope is choice-reaction research, full text unverified | Clarify labels, distinguish alternatives and group by task before hiding choices. Use progressive disclosure only if secondary choices remain findable | Counterexample: hiding all specialist tools slows expert work. No menu-count limit or computed UI completion prediction | Compare choice accuracy, backtracking and completion on representative novice/expert tasks |
| UX-04 | Pointing/target acquisition; DEFAULT WITH OVERRIDE | PROPOSED informed by F2; F1 full text unavailable, no quantitative prediction adopted | Make important targets reachable and distinct; inspect distance, size, adjacency, touch posture and errors alongside accessibility requirements | Counterexample: making Delete largest and closest increases harm. Larger is not always better; A11Y-02 target criterion remains separate | Test near-neighbour mis-taps, keyboard alternative and repeated target acquisition on actual supported devices |
| UX-05 | Recall across steps; DEFAULT WITH OVERRIDE | PROPOSED informed by M1; chunking is contextual | Group meaningful related information and keep required context available. Use recognition and summaries rather than forcing users to remember prior values | Counterexample: arbitrary groups of seven fragment one coherent task. Visible choices are not a memory-span experiment | Ask users to complete a cross-step task; record forgotten values/revisits; no seven-item pass/fail check |
| UX-06 | Discovery/control/feedback; DEFAULT WITH OVERRIDE | PROPOSED informed by N2; broaden beyond four laws | Give controls visible signifiers and outcome-based labels; expose system status, exit and recovery. Keep help near an unfamiliar requirement. Preserve user control; choose defaults for the task rather than conversion pressure | Genuine Undo depends on FLOW-05; hidden expert shortcuts may supplement visible controls | New user discovers main action without guessing; can cancel/back out where promised; confirmation matches actual outcome |
| UX-07 | Hierarchy/progressive disclosure; CONDITIONAL | PROPOSED; information hiding can conceal required work | When collapsing detail, show its purpose and completion/error summary. Distinguish navigation from workflow progression. Label current location and return route | Do not add steps or collapsible sections without task evidence | Error in collapsed applicable section becomes discoverable and focusable; Back preserves permitted work |
| UX-08 | Consequential choices, consent, subscriptions or exits; CONDITIONAL | U9; APPROVED AUTHORING POLICY informed by S5; operable controls can still mislead | Make material consequences, costs and defaults understandable before commitment. Review emphasis, labels, decline/exit/reversal discoverability, genuine urgency and cancellation effort. Challenge concealed choices, false countdowns and unnecessary obstruction | Legitimate risk-based confirmation/security steps remain; no universal equal-click-count rule or claim of legal compliance. D01/D02 supply actual consequences | User can describe what is agreed and decline/leave through the supported path; cancellation is not concealed; conversion improvements do not erase informed choice |

Additional principles considered: visibility, recognition over recall, error prevention/recovery and user control (N2). Their selection addresses concrete failure modes above; this is not a quota of named laws. Speed alone is insufficient: compare correctness, confidence in scope and successful recovery. Usability sessions need representative users; an agent walkthrough is an inspection, not user research.

Use VERIFY-06 in [verification](verification.md) when planning or claiming usability evidence, and A11Y-05 in [accessibility](accessibility.md) for comprehension and interruption. UX-08 expands user-control review using documented dark-pattern failure scenarios; it does not turn a skills audit into a legal assessment. Do not infer a user's understanding from successful clicks alone.
