# Accessibility, device context and performance

Inherit RULE-BASE from [governance](../governance.md). WCAG target/version/level and platform obligations are D04, not assumed product requirements. WCAG 2.2 AA is a proposed starting point for web pilots. This module's subset is not a complete conformance audit. [WCAG 2.2](https://www.w3.org/TR/WCAG22/) defines normative criteria; [APG](https://www.w3.org/WAI/ARIA/apg/patterns/) offers informative widget guidance.

## Web checks to resolve against the selected target

- **Contrast:** for SC 1.4.3, ordinary text requires 4.5:1; qualifying large text 3:1. Inspect exceptions and actual rendered typography; disabled-state exemption does not justify hiding essential information. [WAI contrast guidance](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).
- **Reflow:** SC 1.4.10 uses 320 CSS px width for vertical scrolling or 256 CSS px height for horizontal scrolling, with exceptions for content needing two-dimensional layout. Inspect whole task, not merely a responsive screenshot. [WAI reflow guidance](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html).
- **Targets:** SC 2.5.8 generally uses 24 by 24 CSS px or its spacing condition, with listed exceptions; it is not an unconditional 44 px AA rule. Measure adjacent targets and verify the actual exception. [WAI target guidance](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html).
- **Other targeted checks:** keyboard/no trap (2.1.1/2.1.2), focus order/visibility/not wholly obscured (2.4.3/2.4.7/2.4.11), alternatives to dragging (2.5.7), error identification/instructions/suggestions (3.3.1-3.3.3), status messages (4.1.3), name/role/value (4.1.2), text resize/spacing (1.4.4/1.4.12), non-text contrast (1.4.11), colour independence (1.4.1), redundant entry (3.3.7) and accessible authentication (3.3.8). Apply exact normative definitions and exceptions. [WCAG 2.2](https://www.w3.org/TR/WCAG22/).

Inspect announcements for timing, duplication and usefulness using the actual supported AT. A visible error, `aria-live` attribute, automated scan or build success alone does not prove that users hear or can recover from it. Accessibility covers complete applicable processes, not just the isolated screen changed.

For A11Y-05, record the actual audience, language and task context. [W3C cognitive accessibility guidance](https://www.w3.org/TR/coga-usable/) supplements normative WCAG requirements. Apply the relevant patterns to observed needs; do not add a fixed quota of steps, mandated simplified vocabulary, pop-up help or research participants. Research authority, consent, privacy and evidence limits follow VERIFY-06 in [verification](verification.md).
