All ten U6 candidate policies are carried below as formulations FOR REVIEW, not quotations or universal UX laws. The row strength describes the intended contract once adopted. Where an invariant is independently required by U4/U5 or the user's security/ownership instructions, that requirement still applies; a timing/submit override cannot waive it. ## Form-level state rules

`pristine` means no user attempt/touch according to the selected profile, not a remote claim of validity. `dirty` compares permitted draft to its baseline; it is independent of validity. `submitted` is a user attempt; `committed` is authoritative success. Submission failure must not reset dirty/touched state indiscriminately.

Each form resolves its focus policy (summary with field links, first error, or another accessible approach) and which live announcement is emitted once. Local errors may be computed silently for hints without revealing premature error styling. A remote rejection applies only to the checked value and dependencies; changing another unrelated field does not erase it. A form-level server rejection is not forced onto an unrelated input. See STATE-04 for unknown outcomes.

Mandatory applicable test families under VAL-01 through VAL-09: untouched, partial, required/optional boundaries, both sides of numeric/text limits, corrected, conditional hidden/revealed, pasted/autofilled, cross-field changes, imported review, server rejection, remote pending/outage, out-of-order responses and eventual successful recovery. Test units and normalisation at the real server boundary where available, with supplementary deterministic race tests.
