# Bounded adoption and evaluation

This catalogue distinguishes authored capabilities from later application/runtime evidence. It is not authorization to implement applications, activate automation or mutate live systems.

| Follow-up | Entry condition | Evidence required |
|---|---|---|
| Blind source-only skill evaluation | Authorized evaluator and raw fixtures | Run correct/broken/unrelated/small-change controls from the evaluation catalogue; record actual outputs and rubric, not just expected answers |
| Existing API-to-database pilot | Named repository or user-approved representative flow, read-only scope first | Trace actual owners, middleware, storage guards and consumers; source findings and precise runtime limits without repairs |
| Authorized real-boundary tests | Known test environment, fixture authority and command side effects | Real API/selected database, deterministic contention, reload and affected projections; no mock-only parity claim |
| Migration rehearsal | Confirmed schema change and isolated representative dataset | Legacy upgrade, concurrent edits, old/new compatibility, locking/runtime and actual recovery evidence |
| Provider/queue recovery | Authorized sandbox or controlled broker/provider | Duplicate/order, receipt/ack loss, unknown outcome and reconciliation across actual boundaries |
| Backend hook adoption | Useful manual checker measured with positive/negative controls | Supported event/runtime, scope/time/output limits, dedupe, independent CI, removal and explicit activation; no automatic live operations |
| Ongoing maintenance | Changed source/version, real failure or accepted project feedback | Narrow rule correction, revision lineage and affected checks; preserve framework-neutral scope |

Use the [evaluation catalogue](evaluations.md) and fictional fixtures for independent specification, implementation and verification trials. Measure reference-reading cost across repeated small and cross-layer tasks before adding entry skills or fragmenting modules. A passing structural checker does not establish backend application correctness.
