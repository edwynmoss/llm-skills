# Configuration, observability, lifecycle and recovery

Inherit [governance](../governance.md). Activate this module when backend behavior depends on startup configuration, health, deployment, telemetry, shutdown or operational recovery. It does not turn application work into an infrastructure audit. Record code-owned configuration and live provider observations separately.

## Define what operators need to know

Begin with an actual failure or business outcome. A useful diagnostic should identify the operation, stage, result, correlation and owner without exposing protected input. A counter called success must state whether it counts accepted requests, committed mutations, delivered notifications or completed business work. A timer's last-start timestamp does not establish last-success freshness. Make each signal's semantics stable across code, dashboards, alerts and reports.

Separate operational telemetry from durable audit evidence. Debug logs may be sampled or expire quickly; they may not satisfy traceability for approvals or financial mutations. A durable receipt should link canonical operation and source evidence, with appropriate permissions and retention. Do not introduce an audit database as a default; inspect existing mechanisms and the actual requirement. OpenTelemetry documents minimizing and handling sensitive telemetry data, but instrumentation alone does not create a privacy policy. [Sensitive telemetry guidance](https://opentelemetry.io/docs/security/handling-sensitive-data/).

Correlation must survive the boundaries that matter. A request ID can link incoming handling and immediate provider calls; queued work may need a durable operation ID and a new attempt ID. Preserve the distinction so retries do not look like new business operations. Do not use unrestricted user-supplied correlation strings in logs or high-cardinality metrics. Validate size/format and encode appropriately for the sink.

## Startup, shutdown and configuration

Inspect actual deployment configuration, precedence and secret resolution. A checked-in default, environment override and provider-side setting can disagree. Current local code owns implementation evidence; running configuration owns deployed state. Name which repository must change so redeployment preserves the fix. Do not infer live configuration from a README or a stale environment example.

Classify dependencies as required for accepting specific work, optional for degraded functionality or purely observational. A metrics exporter failure may not need to stop all business traffic; missing encryption keys or wrong database identity may require a startup failure. Resolve the policy, then test it. Avoid silently selecting a production endpoint when a test setting is missing.

For shutdown, trace intake closure, in-flight requests, workers, queues, leases and database transactions. A host can terminate before a long drain finishes; define what remains durable and who retries. A detached asynchronous operation that was never observed can vanish on process exit. Reuse the framework's lifecycle and cancellation support, but verify the application has connected its resources and work ownership correctly.

## Operational verification and limits

Exercise configuration absence, invalid values, dependency outage, timeout, recovery, restart and shutdown within an authorized fixture. Observe both business effects and signals. A health endpoint returning 200 establishes only its implemented checks; it does not prove database integrity, queue freshness or successful downstream delivery. An alert firing once does not prove routing permissions or recovery behavior.

For a release, record implemented, built, tested, deployed, observed and accepted separately. Capture artifact identity and live readback where authorized. A flag can preserve deployment compatibility but still create mixed semantic states; define how records/work started under one flag state behave after it changes. Keep cleanup of expired flags scoped and deliberate.

Document what remains unverified. A backup exists but restore was not rehearsed; a worker is alive but no natural completion has been observed; a code-owned setting changed but production has not redeployed. These are distinct evidence limits and should lead to precise follow-up work rather than a blanket healthy label.
