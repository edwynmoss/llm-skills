# External services, SDKs and storage integrations

Inherit [governance](../governance.md). Apply this module to outbound HTTP/RPC, provider SDKs, object storage, identity/payment/email services and third-party data. Use [dependency contract](../templates/dependency-contract.md). Keep provider facts tied to current primary documentation and observed configuration; familiarity with one SDK version is not proof of another version's behavior.

## Resolve the actual dependency contract

Record provider, API/SDK version, endpoint/environment, account/scope, owning code, credentials reference and canonical IDs. Never copy credentials into the contract. List the operations the application actually needs, including failure and recovery capabilities. A provider may support an idempotency key for one endpoint but not another, or only within a retention window. A status lookup may be eventually consistent or scoped to one account. Those details determine recovery; do not infer them from a marketing claim.

Inspect existing client configuration before adding wrappers. Many SDKs already retry, follow redirects or buffer responses. An application retry around an SDK retry around a queue retry can multiply attempts and cost. Establish one deliberate owner for each retry scope and a total deadline. If the provider imposes a retry-after signal, define how it interacts with the remaining budget and scheduler. Do not invent numeric values without a project decision or measured requirement.

Separate connection failure before dispatch from a timeout after bytes may have reached the provider. The latter can leave an unknown outcome. Use supported idempotency or lookup/reconciliation; if neither exists, report the unresolved operation rather than automatically repeat it. Mapping every exception to false is particularly dangerous when callers interpret false as no effect occurred.

## Boundary design and data mapping

Translate provider-specific response shapes into the application's canonical vocabulary at a focused boundary. Keep enough error detail to distinguish authorization, rate limit, invalid input, conflict, unavailability and uncertain outcome without leaking raw payloads. Stable IDs belong in durable relationships; names and labels are mutable display evidence. When identity matching is ambiguous, preserve it as unresolved and avoid guessing a local entity.

For provider reads, track coverage separately from records. An interrupted page sequence is incomplete evidence, not proof that missing items were deleted. A reconciliation job should apply removals only under its adopted complete-source or explicit-tombstone contract. Inspect pagination tokens, filters, ordering and retry behavior together; repeating a page while data changes can create duplicates that need stable-ID handling.

Object storage has its own publication lifecycle. Define temporary/staged object ownership, size/checksum/type validation, metadata commit, access policy and cleanup. A database row pointing to a partially uploaded file must not be marked ready. Signed URLs have a scope and expiry; revoking a database permission may not revoke an already-issued URL immediately. Make that limit part of the security and UI contract.

## Verification with honest scope

Use contract fixtures for mapping, malformed/missing fields, unknown enums, rate limits and timeout classification. Supplement with an authorized provider sandbox or controlled real boundary when the claim depends on actual authentication, pagination, deduplication or cancellation. Do not call a production email/payment endpoint merely because the unit-test double passed. A provider's test mode can differ from production; record what was actually exercised.

Test the same logical operation across lost response, status lookup, retry and final reconciliation. Check both canonical state and external effect count where the environment permits. Verify a genuine second operation still succeeds and that another tenant's key or receipt cannot be replayed. For read-only review, stop at source facts and a precise runtime hypothesis when live scope is unavailable.

Keep source-owned configuration and deployment state distinct. A repaired adapter in a checkout does not prove a running worker uses it. Record reviewed revision, deployed artifact and provider observation separately. Reuse existing schedulers, ledgers and notification producers; integration work is not authorization to create a parallel pipeline.
