# Middleware, filters and request context

Inherit [governance](../governance.md). Middleware includes request interceptors, filters, guards and framework pipelines. Apply the platform's actual execution model rather than imposing one universal order. Use [request pipeline](../templates/request-pipeline.md), with security, API and operations modules where affected.

## Build the ordering contract

Write the actual sequence from the ingress boundary to the handler and back. Include reverse proxies, gateways and framework modules when they own limits, TLS termination, forwarded headers or identity. Record what each stage requires and produces: a request ID, raw body, principal, tenant, parsed input, endpoint metadata, database scope or response headers. Dependencies determine ordering; a generic diagram cannot establish a specific framework's route-selection or exception-unwind semantics.

Document bypasses deliberately. An authorization stage may not run for a missing route; an exception stage may not catch an upstream proxy rejection; a preflight request may follow a separate policy. A health endpoint may intentionally be anonymous but must not expose detailed configuration. Public downloads, WebSocket upgrades, streaming endpoints and webhook routes can use distinct paths. Inspect those paths before claiming a global middleware registration protects every surface.

Create an event trace in an authorized fixture: stage entered; input context; downstream invoked or short-circuited; response state; cleanup. Use assertions on order and effects rather than matching implementation source strings. Ensure denied requests never reach prohibited business mutations. Where a check requires loading a record, verify both its tenant selector and subsequent object/field authorization. Authentication cannot establish ownership simply because the client supplies an object ID in a signed token or header.

## Context, cancellation and trust

Never treat an incoming tenant header or forwarded client address as authoritative without the configured trust boundary. Verify how proxies are identified and how chains are interpreted. A rate limiter keyed on an attacker-controlled field can be bypassed; a limiter keyed globally can let one noisy tenant deny others. Do not select a rate-limit algorithm or limit value from this library. Record the product/operational policy, shared-store behavior and what happens if the limiter dependency is unavailable.

Use immutable request context or the framework's scoped equivalent. A singleton mutable CurrentTenant property is unsafe when requests interleave. Async-local context needs correct initialization and cleanup; it should not be assumed to survive queue handoff or detached tasks. Pass durable job context explicitly with provenance and authorization semantics. Avoid copying credentials or entire request bodies into background envelopes.

Cancellation is a request to stop work, not proof that nothing committed. Determine whether the framework propagates disconnects to the use case and database call, whether the driver honors them, and what occurs after commit or external dispatch. Cleanup belongs in guaranteed lifetime handling. A cancellation callback must not send a second response or mark a possibly committed operation failed without evidence. Use the concurrency module when a client might retry after interruption.

## Focused verification matrix

Cover normal success, malformed input, absent identity, invalid identity, insufficient permission, cross-tenant ID, unknown route, deliberate anonymous route, preflight, dependency failure, handler exception and client disconnect as applicable. Check headers and status after each path, including errors raised before routing. Test a valid request alongside each denial control so over-restrictive middleware is not mistaken for correctness.

For signed webhooks, retain the exact body representation required by the provider in the fixture and prove that parser or compression configuration does not change verification input. Test a tampered body and a valid retry separately. Signature verification, replay detection and business deduplication are different responsibilities. A successful signature does not prove the event is new, ordered or authorized to select arbitrary local entities.

Credit existing framework behavior. If the framework already disposes request scopes or centrally maps errors, verify that integration before adding a second wrapper. Middleware should make cross-cutting behavior observable and consistent; it should not become a hidden application service or a second place to define business truth.
