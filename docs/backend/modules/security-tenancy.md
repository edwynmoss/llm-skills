# Authorization, tenancy and untrusted boundaries

Inherit [governance](../governance.md). This module provides engineering verification guidance, not an independent security certification or legal retention policy. Use the actual identity provider, authorization owner and deployment boundary. Link the [service contract](../templates/service-contract.md) to the relevant permission matrix and [acceptance evidence](../templates/acceptance.md).

## Trace identity all the way to the effect

List the principal types and how each is authenticated: anonymous caller, end user, support operator, service account, scheduler, webhook provider and migration operator where applicable. Record which identity supplies the tenant and whether a caller can legitimately act across tenants. A partner relationship, shared host or common repository organization does not merge application access. Server-side scope must survive every translation into a command, query, background envelope or remote request.

Build a matrix of principal × operation × object relationship × field × lifecycle state. Do not reduce authorization to endpoint roles if ownership or approved-state rules also matter. Validate that alternate endpoints, bulk operations, exports and background consumers use the same policy. An object may be readable while a particular field is protected; a caller may create a record without being allowed to choose its owner or approval status. Default-deny and per-request checks are established guidance, but the project's domain defines the actual permission policy. [OWASP authorization guidance](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html).

Pair read and mutation checks for the same canonical entity and principal. Compare each operation with its adopted policy, including private/disabled parents, expired membership and alternate callers. A guarded read does not prove a write is guarded, and hidden UI actions do not supply authorization. Read and write permissions need not be identical: a deliberately public projection with an owner-only mutation is a valid positive control. Inspect shared guards before reporting a missing leaf-level check; denied mutations must leave canonical state and prohibited downstream effects unchanged.

Tenant isolation needs more than a request filter. Inspect joins, subqueries, aggregate counts, raw SQL, administrative bypasses, soft-deleted rows, relationship assignment, cache keys and object storage. If database row-level security is used, inspect the actual execution role, bypass permissions, connection pooling and transaction/session context. Do not assume an ORM filter or row policy covers every raw query or privileged connection. Conversely, credit a verified shared guard rather than reporting each leaf query as an independent missing filter.

## Dangerous ambiguity to resolve

Decide whether not-found and forbidden responses intentionally hide resource existence. That decision must remain consistent across list counts, errors, timing-sensitive lookups and exports where material; the skill must not prescribe one universal HTTP status. Decide whether a queued action runs with a durable authorized delegation or checks the initiating user's current permission. Both can be legitimate in specific systems, but capturing a stale request token by accident is not a decision.

For outbound URLs, identify whether callers may select arbitrary destinations, only named providers, or a constrained set of resources. Validate redirects, resolved destinations and network boundaries using the platform's supported mechanisms when SSRF is relevant. A string prefix check is not a complete network authorization policy. Do not add a custom URL parser or crypto routine where an established component supplies the needed capability.

Secrets must not enter fixtures, migration files, logs, example commands or saved reports. Redaction should occur before records leave the trusted boundary; downstream masking cannot recall already-exported data. Correlation identifiers should be opaque and bounded. Avoid putting tenant/user IDs in high-cardinality metric labels merely for debugging. Persisted audit records and operational telemetry have different access and retention needs; resolve both explicitly.

## Positive and negative verification

Use synthetic principals and records with deliberate overlap: identical display names, local child IDs or cache query parameters across two tenants. Attempt read, update, delete, link, export, count and asynchronous execution only where authorized in a test environment. Include the legitimate same-tenant and permitted shared-resource controls. A system that denies everything has not passed functional authorization acceptance.

Test permission changes during a long-running workflow against the adopted policy. Check whether cached fields, generated files and signed URLs remain accessible after revocation and whether that lifetime is intentional. Do not claim immediate revocation if a provider URL remains valid until expiry. Record what the boundary actually guarantees and what remains an operational risk.

A security review can identify dangerous source construction without executing it. Report the precise dataflow and conditions rather than inventing an exploit outcome. A complete source audit report does not grant permission to attack a live environment or certify its deployed configuration.
